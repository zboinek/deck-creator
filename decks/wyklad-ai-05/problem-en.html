The problem

“Reply with JSON only” works. Almost always

The extraction from L10, step 1, run on 1000 recipes. Typical results that will show up sooner or later.
1. A polite preamble
Here is the data in JSON format:

{"title": "Zucchini fritters",
 "ingredients": ["zucchini", "eggs",
   "flour", "salt"],
 "time_min": 30,
 "category": "dinner"}
json.loads → JSONDecodeError
The model is trained on conversations, so it converses. The program crashes on the first character.
2. A markdown block and a comment
```json
{"title": "Banana bread",
 "ingredients": ["bananas", "flour"],
 "time_min": "about an hour",
 "category": "bread"}
```
Time depends on the oven.
JSONDecodeError, then str instead of int
A regular expression can cut it off. Until the next odd case.
3. Valid JSON, wrong values
{"category": "Bread"}
{"category": "bread"}
{"category": "loaf"}
{"category": "baked goods"}
{"category": "bread / dessert"}
parses without an error
The worst case: nothing crashes, and the database has five categories instead of one. The filter from L10 stops working.
Errors 1 and 2 are loud: the program crashes and someone notices. Error 3 is silent: it comes to light weeks later, when the “bread” filter misses half of the loaves.
With 1000 recipes even 1% of errors is 10 recipes that someone has to find and fix by hand.
request ≠ guarantee
